# yw-QR-pwn

## 概要

妖怪ウォッチシリーズの複数作品で、ゲーム内QRコードリーダーに共通するヒープバッファオーバーフローの脆弱性がある。  
細工したQRコードを読み込むことで、隣接するヒープ領域を上書きし、ゲームプロセス内の制御フローを変更できる。

## 確認済みの対象

* 妖怪ウォッチ2 真打（日本語版）v1.2
* 妖怪ウォッチバスターズ 赤猫団（日本語版）v2.3
* 妖怪ウォッチ3 スキヤキ（日本語版）v4.0

## 脆弱性の詳細

デコーダは、ひとつのQRコードから取り出した各データのポインタと長さを記録し、ひとつの結果格納領域へ順に連結する。

Structured Append（データを複数のQRコードに分けて記録する機能）の管理情報を解析した後、その管理情報バッファを指す一時ポインタがクリアされない。そのため、続くByte Mode(QRコードの規格でデータを8ビット単位で符号化する方式)のセグメント解析で入力不足を検出しても、管理情報バッファのポインタとQRデコーダが解析している入力ビット列に記された長さが有効なセグメントとして登録される。

結果を格納する構造体全体の確保サイズは7,128バイトで、データの連結先はその先頭から37バイト後にある。しかし、連結処理は累積出力長とコピー先の容量を比較せず、登録されたポインタと長さを使ってコピーを行う。

データの連結部分を簡略化すると、次のようになる。

```cpp
size_t offset = 0;

for (const Segment &seg : data_segments) {
    memcpy(dst + offset, seg.data, seg.length);
    offset += seg.length;  // コピー先の残り容量を検査しない
}
```

このため、不正な長さでコピーが行われ、結果構造体の外側が上書きされる。呼び出し元のデコーダは連結後に合計長を検査するが、コピーはすでに終了しており、エラーと判定しても範囲外の書き込みを防げない。

## 影響

範囲外の書き込みで隣接するヒープブロックの管理情報を改変すると、解放処理を通じてゲーム内のオブジェクト参照を書き換えられる。これにより、QRデータ内に配置した偽のオブジェクトを参照させ、関数呼び出し先を変更できる。
